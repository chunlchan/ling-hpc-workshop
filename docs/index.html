Counting bigrams on a cluster

Your first HPC job: written by an AI agent (pi), submitted by you

What is a bigram?

A pair of consecutive words.

the cat sat on the mat and the cat slept
the cat ×2 cat sat sat on on the the mat mat and and the cat slept

10 words → 9 bigrams (8 distinct)

What your job does

  • Reads 3,999 passages (about 5,000 words each) from Project Gutenberg books: 19.5 million words
  • Counts the word pairs inside each passage and adds them up
  • Prints the top 20 bigrams and saves the top 1,000 to a file

The linguistics is simple on purpose. The point is the workflow: request resources, submit, wait, read results.

What happens when you submit

You: sbatch→ Queue (PD)→ Compute node (R)→ Results in /N/scratch/$USER

pi writes the scripts. You run sbatch: pi is set up so it cannot submit the job for you.

Get the prompt, edit it, give it to pi

1. Save the prompt

In Firefox on the Research Desktop: Open the prompt ↗

Press Ctrl+S and save it as prompt.txt anywhere you'll remember. Or, in a terminal:

wget -O prompt.txt https://raw.githubusercontent.com/chunlchan/ling-hpc-workshop/main/AGENT_PROMPT.md

2. Edit prompt.txt

Replace each <...> including the angle brackets. Click a value to copy it.

<PATH>
<PARTITION> (or debug if general is busy)
<ACCOUNT> (or your own allocation; ask if unsure)

Then delete the header: everything above the --- line at the top of prompt.txt, plus that line. Keep the rest.

3. Start pi in an empty folder

mkdir -p ~/bigrams && cd ~/bigrams
PATH=/N/project/rpworkshop/guard:$PATH pi

The PATH=... part stops pi from submitting jobs for you. Already in pi? Restart it from here. Then paste all of prompt.txt into pi.

Before you submit: check the batch script

1. Look at the script pi wrote

In the file manager, open the folder where you started pi (~/bigrams). Double-click run_bigrams.slurm and choose Display.

Choose Display, not Run or Execute: the script is meant to be submitted to the cluster, not run here.

Or, from a terminal:

cat ~/bigrams/run_bigrams.slurm

2. Confirm it matches what you chose

  • --partition is your partition (general or debug)
  • --account is c02318 (or your own allocation)
  • --cpus-per-task=1, --mem=4G and --time=00:10:00
  • a module load python/... line, and no module purge
  • CORPUS_DIR is the path you put in the prompt, and OUTPUT_DIR is /N/scratch/$USER
  • --output and --error point to /N/scratch/%u/...

Something wrong? Tell pi what to fix, and ask it to update the script before you submit.

Run it, then check your answer

pi prints commands. Run them one at a time.

Exit pi first, or use a second terminal. pi can't run sbatch.

Submit the job

sbatch run_bigrams.slurm

Watch the queue: PD = waiting, R = running, gone = finished

squeue --me

Read the results (use the job number sbatch printed in place of <jobid>)

cat /N/scratch/$USER/bigrams_<jobid>.out

Your numbers should match

Documents (lines): 3,999 Total bigrams: 19,500,939 Distinct bigrams: 5,306,726 Most frequent: "of the" (177,785) Runtime: about 30 s (varies)

Your output layout may differ from your neighbor's. The numbers should not.

Press ↓ for the fallback and troubleshooting

If the corpus path doesn't work

Permission denied, folder not found, or very slow? Download your own copy:

mkdir -p ~/ling_corpus && cd ~/ling_corpus
wget https://github.com/chunlchan/ling-hpc-workshop/releases/download/2026-10-12_01/prepared_4k_concat.zip
unzip prepared_4k_concat.zip
ls prepared_4k_concat | wc -l
echo $PWD/prepared_4k_concat
  • The wc -l line should print 40.
  • The last line prints the path to use. Put it in place of <PATH>, then start again in a new empty folder.

Stuck?

  • Job stays on PD a long time: the cluster is busy. Ask about the debug partition.
  • Found 0 documents or "no .txt files found": the corpus path is wrong. Check it with ls.
  • python: command not found: the batch script needs a module load python/... line. Ask pi to fix it.
  • Anything else: read the .err file in /N/scratch/$USER, or ask an instructor.
